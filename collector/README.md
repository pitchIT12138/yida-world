# 部署端知乎网页读取器

> 当前定位（2026-09-07）：读取器是折叠的可选能力。用户已要求以普通复制粘贴为演示主路径，默认导入不会启动扫码或联网读取。下文保留读取器运行与历史验证说明。


回答链接的普通 HTTP 响应可能是 JavaScript 校验页。读取器使用独立 Chromium 配置目录执行页面正常加载流程，展开目标回答，再将正文 HTML 交给同一导入校验器。它是产品后端组件，不使用 Codex 浏览器扩展，不读取操作者日常浏览器的配置，评委电脑无需安装组件。

## 本地运行

在 web 目录执行一次 `npm run collector:install` 安装所需 Chromium。

运行 `npm run collector`，再在另一终端运行 `npm run dev`。本地开发服务器自动读取 `.cache/collector/token` 连接读取器；令牌不会返回前端。

推荐在网页“导入回答”中用知乎 App 扫码，再粘贴分享链接；也支持先粘贴，扫码成功后自动继续。扫码状态通过页面已显示的账户入口判断，链接读取复用同一会话和页面，自动打开、展开目标回答并返回正文；不再要求点击“打开这条回答”或“导入当前回答”。登录后扫码窗口自动收起，连续导入无需重复登录。用户于 2026-09-07 实际确认 App 扫码登录成功；短信验证码 10001 不作为推荐演示路径。

每位访问者使用独立的内存浏览上下文，不复制日常 Chrome Cookie。关闭导入面板仍保留本页会话；主动断开、离开网页、10 分钟无操作或创建满 1 小时会清除。画面／状态轮询不延长闲置期限。前端只在内存保留随机会话标识，不放入地址或本地存储；会话过期时保留待读链接，重新扫码后自动继续。读取器重启会使现有会话失效。


原有自动读取器如需操作员登录，先停止当前读取器，再运行 `npm run collector:login`。这会打开读取器自己的知乎窗口，使用正常登录流程；登录完成后服务继续运行。登录状态位于被 Git 忽略的 `.cache/collector/browser-profile`。它不是评委电脑的前置安装要求。

## 与网页分开部署

Cloudflare Worker 不能直接启动本地 Chromium。该 Node 服务应运行在支持 Chromium 的主机上，网页后端通过 HTTPS 调用它：

- 网页后端配置 `COLLECTOR_URL` 与 `COLLECTOR_TOKEN`。
- 读取器配置同一个 `COLLECTOR_TOKEN`，至少 32 字符；只在部署端 Secret 中保存。
- 服务默认监听 `127.0.0.1:7337`，可用 `COLLECTOR_HOST`、`COLLECTOR_PORT` 调整；对外运行时由 HTTPS 反向代理转发。
- `COLLECTOR_DATA_DIR` 指定独立状态目录；需要保留正常登录状态时持久化该目录。

所有读取器 HTTP 接口受 Bearer 令牌保护。自动读取使用 `GET /health` 与 `GET /answer?url=...`。回答输入只接受知乎回答 URL／ID，自动读取的页面请求仅允许知乎及其 CDN 域。单次最多 55 秒，一次处理一篇，拥塞会返回可重试错误。

## 手动窗口接口

读取器提供 `POST /sessions` 创建会话、`GET /sessions/:id/screen` 返回 JPEG 画面、`POST /sessions/:id/action` 接收人工输入、`GET /sessions/:id/status` 检查登录状态、`GET /sessions/:id/answer?url=...` 在同一会话自动读取指定回答、兼容接口 `POST /sessions/:id/capture` 读取当前回答，以及 `DELETE /sessions/:id` 清除会话。最多同时 3 个窗口，单窗口操作串行。没有执行任意控制台脚本或导出 Cookie 的接口。手动窗口额外允许实际登录页使用的网易验证码资源 `cstaticdun.126.net` 及公开加载器列出的验证服务域名；仍由用户完成验证。资源依据真实登录页请求、[易盾官方示例](https://github.com/yidun/captcha-php-demo/blob/master/index.php)和[公开加载器](https://cstaticdun.126.net/load.min.js)核对。

网页后端通过 `/api/manual-browser` 代理以上操作。服务端令牌不会转发给访问者；操作要求同源及自定义请求头，会话通过 `X-Reader-Session` 请求头传递。页面画面和响应均禁止缓存。登录凭证输入仅在本次用户操作中转发至读取器，生产部署必须让网页和读取器都通过 HTTPS，并避免代理记录请求体／会话请求头。

此处嵌入的是独立浏览器的画面和输入控制，不是让父页面跨域读取知乎 iframe。远程浏览器仍可能遇到知乎的校验或访问限制；提供正常登录入口不等于保证通过校验。只读取使用者粘贴链接指定的目标回答，由读取器自动打开和展开，后续原媒体下载和完整性核对沿用同页导入面板。

## 验证边界

`npm run test:collector` 使用真实 Chromium 与受控 HTML 响应，验证 JavaScript 跳转、点击展开、完整末段和原图地址保留、排除其他回答。这个测试不会代表真实知乎请求成功。

2026-09-07 对用户提供的豆丁回答进行了实际匿名读取；普通 HTTP 返回过 `zh-zse-ck` 校验页，独立读取器测试仍未取得目标正文。因此链路已实现，但当前网络下的任意分享链接全文成功率尚未验证，不能把受控测试当作线上验收。

`npm run test:manual-browser` 用真实 Chromium 与受控页面验证画面传输、人工输入、手动展开、原图地址、目标回答隔离、会话隔离、关闭和闲置过期。2026-09-07 手动服务经网页代理实际打开了知乎登录页并返回可显示的 JPEG；未登录时打开给定豆丁回答仍未取得正文，返回 `ANSWER_NOT_LOADED`。尚未完成账号登录后的真实全文导入验收。
