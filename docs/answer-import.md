# 知乎回答导入：探索结论与实现验收

## 当前入口：普通复制粘贴优先

2026-09-07 用户明确要求重新采用 boring 技术，避免演示依赖知乎风控。当前主入口改为“在正常知乎网页展开回答 → 普通复制正文 → 粘贴到本页”。用户无需复制源码；平台接收粘贴事件携带的富文本或纯文本。分享文案只补充出处、作者和标题，不启动读取器。支持先贴正文后补出处，也支持先贴分享文案再贴正文。

扫码和链接读取保留为折叠的可选尝试，只有显式点击读取才会连接；下方关于扫码自动读取的记录是历史探索证据。真实 App 扫码后已观察到自动导航，但目标回答返回 403，不能据此宣称任意链接全文导入成功。

正文解析与保存不需要知乎 API。图片是否随复制提供取决于实际剪贴板数据；外链图片仍可能失败，完整离线媒体需另行保存／补充。本页不把缺失媒体声明为已完整归档。

验证：`npm run test:paste-import -- /path/to/source.html` 可用本地原材料运行真实 Svelte 界面测试，将其正文作为剪贴板载荷导入，拦截全部 API 与外站请求，并比较保存前后所有文字。该测试验证导入端，不等同于操作系统原生复制已包含整篇和全部媒体。组件测试验证默认无网络导入、分享文案不充当正文、先正文后出处及可选读取失败后的正文导入。


记录日期：2026-09-07。目标是评委在自己的电脑上选择真实知乎回答，将全文、图片及其他原内容带入同一个页面，并可导出到本地。用户最新确认三种入口：回答底部分享文案／链接、网页 HTML、正文文本。评委端不要求预装扩展。

## 结论

分享文案可整段粘贴，识别问题标题、作者和准确的回答 ID，包括用户给出的 Markdown 链接格式。分享文案只作为定位输入，不会被保存为回答正文。失败后保留来源及署名，继续粘贴 HTML 或正文即可补充同一篇回答。

已实现“普通 HTTP → 部署端 Chromium 网页读取器”的链接读取链路。读取器执行正常网页加载、展开目标回答，并提取富文本。它可以在自己的独立配置目录中正常登录，运行位置属于产品部署端，不依赖评委或 Codex 的浏览器扩展。详见 [读取器运行说明](../collector/README.md)。不再将官方全文接口作为实现前提。

当前推荐同页知乎 App 扫码，再粘贴分享链接；支持先粘贴后扫码。两者共用同一浏览器会话，登录后自动打开并展开目标回答、返回正文，扫码窗口随之收起。各访问者会话隔离，关闭导入面板保留本页登录，主动断开／离开网页／会话过期时清除。普通跨域 iframe 不能让父页面注入脚本或读取知乎 DOM，依据 [浏览器同源策略](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)；因此不使用跨域 iframe 假装完成提取。

“普通复制／HTML → 带图导入 → 本地保存”已实现。部署端读取器也已接入，但真实知乎样本请求仍未取得正文，因此“任意回答只给链接即可稳定取得全部内容”的验收尚未完成。

## 检查过的路径

| 路径 | 证据与结果 | 对评委演示的意义 |
| --- | --- | --- |
| 官方 OAuth | 本地官方资料规定授权页、后端换 Token 与 `X-OAuth-Token`；用户内容列表字段为 `Summary` | 可以做登录和选择本人内容，不能据此承诺任意回答全文 |
| 官方内容、收藏和搜索 | 检查了开放平台在线文档；内容／收藏提供摘要，搜索 `ContentText` 也被定义为摘要 | 可提供索引与定位，摘要不能作为完整原文 |
| 比赛知识／故事接口 | 真实请求成功，样本返回约 3,000 字的章节／片段 | 保留为辅助入口，标记片段 |
| 官方 PPT 能力 | 接受回答 URL，但输出是演示文档 | 转换结果不能恢复成无损原文 |
| 回答页面和站内接口 | 普通 HTTP 的某次 403 实际为 `zh-zse-ck` JavaScript 校验页，不能直接归因于登录。其他请求也出现过明确访问限制／登录错误 | 已区分页面校验、实际登录和访问限制；网页读取器负责执行正常加载流程 |
| 部署端网页读取器 | 已实现并启动独立 Chromium，实际匿名请求仍未得到目标正文；受控页面验证执行 JS 跳转、展开与正文提取 | 评委只输入分享文案；不依赖评委设备安装，但实际网络成功率仍待验收 |
| 同页手动窗口 | 新增真实 Chromium 独立会话；实际成功显示知乎登录页，匿名打开目标回答仍未取到正文 | 评委可在本页正常登录和操作，无需扩展或复制 Cookie；真实登录后的导入待验收 |
| 短链接 | 本次读取也失败；当前导入器支持完整回答链接与数字 ID | 分享短链尚不是可靠入口 |
| 知乎网页复制处理器 | 分析了网页 bundle 的复制逻辑，选区会写入 `text/html` 与 `text/plain`；达到一定长度会附署名与原链接 | 浏览器普通复制就可能提供富文本，不必让评委复制源码 |
| 用户提供的实际页面 | 渲染 DOM 有 5 个回答，初始数据仅有 1 个；实际解析出 5 个独立回答 | 只依赖 `js-initialData` 会漏掉该样本的其余回答 |
| 原图下载 | 从样本中优先识别 `data-original`，真实取得 34,782 字节 JPEG | 文件本身已进入导入样本，离线导出不是保留外链 |
| 操作 Chrome | 当前控制扩展未连接，没有完成真实 Chrome 选区复制验收 | 不宣称已在用户浏览器完成实测；组件交互测试使用模拟 DOM |

资料入口：[知乎开放平台](https://developer.zhihu.com/)、[在线文档数据入口](https://developer.zhihu.com/console/api/v3/docs)。仓库内配套资料：[黑客松 OAuth](../../zhihu/references/hackathon-oauth.md)、[用户数据 API](../../zhihu/references/user-api.md)。复制逻辑来自本次页面引用的 [知乎 main.app bundle](https://static.zhihu.com/heifetz/main.app.3c4624001fcdda593697.js)，该文件名属于当时页面版本，不作为长期接口。

## 同一页面内的使用流程

1. 点击“导入回答”，粘贴回答底部“分享”得到的整段文案、完整链接或 ID。也可直接在知乎展开全文后复制正文，或粘贴网页 HTML 源码。
2. 点击“扫码登录知乎”后粘贴分享链接，或者直接粘贴链接并完成出现的二维码登录，之后自动读取，不需要在小窗口里打开或导入回答。也可以在正文框粘贴。平台优先识别富文本，保留标题、段落、强调、引用、列表、代码、表格、图注、图片、支持的音视频和 MathML。只有纯文本时会保留纯文本，不会凭空补图。
3. 检查署名和来源；若文件含多篇回答，可选择目标。展开预览，核对全文后勾选确认。
4. “保存全部原媒体”读取图片／媒体字节。失败项保持可见，可重试或补充本地原文件；取消操作保留已下载媒体。
5. “加入本页”保存到当前浏览器。回答卡片内可以重新核对原文、继续下载媒体和导出。
6. 完整性已核对、没有已知缺失且所有外链媒体已保存时，开放 ZIP 下载。解压后打开 `index.html` 离线阅读；ZIP 也可以重新导入平台。未完成时可导出 JSON 保留进度。

没有新增管理页、账户中心或后台列表。读取器运行在部署端；当前流程不依赖 OAuth 接入。

## 已实现的内容保留与边界

- 不再按旧的 60 段／18,000 字限制截取导入原文；富文本上限 4 MB、纯文本合计上限 100 万字、最多 10,000 个段落，超限明确拒绝。限制是处理能力边界，不以静默截断应付。
- 图片优先使用原图地址；支持内嵌栅格图片。正文会显示已保存图片的本地 Blob，不再依赖原图服务器。
- 外链媒体每个最多 20 MB、合计约 100 MB。下载代理只允许知乎 `zhimg.com` 域及子域，校验重定向和文件格式。其他域可通过已有媒体项手动补充原文件。
- ZIP 包含原文 JSON、媒体文件、独立阅读 HTML 及已有生成产物记录；媒体用 SHA-256 校验。重新导入检查媒体是否缺失、文件是否损坏及生成产物是否匹配原文。
- 保留的是安全的正文结构，不是知乎页面像素级复刻。网页脚本、界面按钮、事件属性等不会进入正文；样式被规范化。
- 嵌入播放器现在可以补充原音视频文件，平台在原位置呈现本地播放器并保留原始链接；离线 ZIP 包含音视频文件和播放器。只有全部嵌入媒体补齐时才消除该项缺失状态，其他缺失提示继续保留。图片不能替代完整音视频通过校验。
- 没有文件地址的图片／音视频会保留正文位置和本地附件标识，可以逐项补充原文件，再导出和重新导入。标识不会伪装成知乎来源链接，也不会被发送到网络下载接口。
- 尚未支持完整归档所有自绘 SVG／canvas、交互式嵌入对象及大媒体。识别到无法处理的对象时标为待补全，不能下载“完整包”。现有播放器补全方式需要用户提供对应原文件，不会自动从任意播放器提取文件。
- 原文图片已经支持显示和归档；生成接口仍发送原文数据与图片地址，不代表模型已接收到并理解图片像素。
- “已核对全文”是导入者确认，不是平台能够凭链接证明的服务端保证。复制遗漏而又手动勾选的情况无法自动排除。
- 本地保存不提供跨电脑同步。换电脑可以导入 JSON／ZIP；线上部署及部署环境中的知乎访问能力尚未验收。

## 实际验证

`npm run check`：0 错误、0 警告。

`npm test`：11 个测试文件，79 项通过。覆盖用户提供的分享文案、Markdown 链接、分享文案不充当正文、HTML 源码粘贴、读取器转发与来源校验，以及此前的富文本、媒体保存、ZIP 往返与错误处理。剪贴板组件交互使用 jsdom 模拟；音视频测试检查文件及播放器结构，不证明实际 Chrome 解码播放通过。

`npm run test:collector` 使用产品的真实 Chromium 读取器与受控网页响应，检查 JavaScript 跳转、展开目标回答、保留末段与原图、排除其他回答。它与真实知乎访问结果分别记录，不用于证明线上链接读取成功。

`npm run test:manual-browser`：真实 Chromium 与受控页面验证人工输入、手动展开、图片与末段、目标排他、窗口隔离、关闭和过期；模拟 DOM 组件测试验证直接输入、中文组合提交、实时指针传递、关闭面板保留会话及主动断开。

真实手动服务通过应用代理成功创建会话、取得知乎登录页 JPEG、删除会话；未登录时导航到用户给定回答，读取返回 `ANSWER_NOT_LOADED`。这不是登录后的全文成功记录。

`npm run build`：成功。Vite 仍提示未来原生配置加载兼容性与客户端主包超过 500 KB，不影响本次构建，但不应隐去。

用户提供的真实页面提取出 5 个回答，原始回答 ID 均以字符串保留。包含图片的回答 `2079546263855547652` 已取得原 JPEG：

```text
bytes: 34782
SHA-256: 218dc1c3aaaaffcf846b33ab317fdca59649831ca17900dbc30a70968628b677
```

实际导入样本保存在 `artifacts/zhihu-real-import.local.json`，包含 5 篇回答和该图片的字节数据，保留“待核对”状态。该本地文件被 Git 忽略，不随构建公开。没有拿未经核对的真实样本伪造完整 ZIP 验收。

## 剩余验收

需要在实际部署网络中完成真实分享链接的正文读取、原媒体保存、断网阅读及重新导入。当前同页手动窗口已经实际显示正常网页登录入口，但本次没有操作账号登录，匿名网络没有取得用户样本全文。原文复制与文件导入仍可使用。

特殊交互式嵌入对象及大媒体的完整归档也仍未覆盖。保留这些验收项，不用摘要、测试页面或预置样本替代“现场随机选择真实回答”的要求。
