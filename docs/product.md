# 一答一世界｜产品说明

## 项目命题

知乎里的回答常常在解释变化、过程、选择与经验。静态文字可以讲述，却不总能让读者亲自验证。我们尝试让程序成为创作者直接使用的另一种表达语言。

作者写下文字，Agent 理解这篇具体内容，自行决定是否用轻交互、图文联动、小型实验或局部叙事增强表达。生成的程序嵌入回答正文，读者保持原来的阅读路径。

## 目标用户与价值

- 创作者：把难以说清的过程和关系变成可体验的表达，无需学习代码。
- 读者：通过操作理解文章，主动提出另一种表达要求。
- 社区：丰富原有回答的内容形式，同时保持作者、原文与来源的连续性。

价值判断不是“生成的程序有多复杂”，而是“它是否让这篇文章更容易被理解”。知乎式宿主保持一致，每篇回答的局部视觉由 Agent 决定。

## 核心流程

写下或导入原文 → 让这篇回答活起来 → 查看可运行结果与加工说明 → 输入自然语言修改 → 导出或保存个人预览。

选取连续段落可以限制加工范围。失败保留原文和上一版。变化回放只展示已完成的加工，明确区分缓存回放和当前请求。

## 技术方案

宿主：Svelte 5、Vite、TypeScript、普通 CSS。

服务端：单个 Cloudflare Worker，代理模型与官方内容接口，执行结构／语法校验和至多一次修复。

表达运行：每个回答中的 HTML/CSS/JavaScript/SVG/Canvas 在同一套 sandbox iframe 中执行；通过限定消息更新尺寸、阅读状态和声明过的正文数值。

Agent 首版没有图片生成 API、素材搜索或在线 npm。视觉和交互代码都在它读完原文后生成，不能提前准备题材组件冒充结果。

## 精选与实时

当前默认精选由用户授权的 Codex 会话读取 17 篇原文与备注后创作，并通过统一校验与运行环境保存。来源标注为会话生成，没有伪造 API 记录。连接模型后的准备流程可以改用 frontier API 反复加工，线上默认 balanced API；交付格式和运行环境相同。

## 知乎连接

知识／故事列表和详情由比赛官方接口读取。保留原作者和片段属性。原创示例使用虚构人物与明确假设。首版免登录、不接主站发布接口，站内赞同、评论和收藏仅为本地原型交互。

## 当前完成边界

已实现宿主、模型调用代码、内容导入、默认会话产物及验证工具。17 篇默认内容可直接运行，共 45 个片段；示意图用代码绘制，图片比较使用保存的原图，保留原文与来源。尚未配置在线模型，因此当前会话生成不代表网页已可实时调用 Codex，也不代表完成 API 模型质量评测。

比赛提交版本还需补齐在线生成与自然语言修改的真实 API 验收、正式部署地址、实际手机设备及网络检查和演示视频。
