# 一答一世界

让知乎回答里的知识，变成你能亲手探索的世界。

团队：网页复健中心。参赛主题：知识炼金场、跨次元游乐场。

## 创作动机

我们在知乎读到过很多好回答，也收藏了很多，却未必真正理解其中的推导。人口结构改变后，供养压力如何变化？同样三十年的收入，为什么不能直接相加？故事里的人物为什么会认错眼前的人？有些问题需要读者亲手改变条件，才能看清原因。

一答一世界尝试把程序作为回答的另一种表达方式：保留作者的原文、原图和来源，在论点附近加入可以操作的比较、推演和场景。读者改变一个条件，看见反馈，再回到原文核对。这种体验既服务于知识理解，也适用于叙事阅读。

## 产品体验

游客无需登录即可阅读公开精选。首页优先展示五篇真实回答，依次是 DLSS 图片比较、老龄化、现金流折现、租售比和国考分析，随后是故事与原创演示，共十七篇阅读体验。首篇直接展示真实原图和拖动分隔线；每篇的核心操作前置，其他交互随原文展开，不藏在折叠正文里。

重点案例：

- **DLSS：把判断交给观察。** 读者拖动分隔线、同步放大、联动平移或并排查看作者原图。图片是否同一时刻、配对是否明确都会说明，截图比较不冒充性能测试。
- **现金流：亲手改变某一年。** 选择年份修改金额，或调整收入、支出、增长与折现率，年度曲线和总现值一起变化。可以保留原方案比较，手动覆盖的年份单独标记和撤销。默认 4% 是演示参数；计算现金流，不衡量人的价值。
- **老龄化：分清口径再推演。** 使用原文年份数据作为基准，读者调整人群结构并保留两种情景，观察人口图形、供养关系与负担。不同年龄、缴费和领取口径分别展示；情景实验不冒充完整人口预测。
- **近视故事：探索同一空间里的信息差。** 读者观察物件、推进情节，切换人物所见与读者已知，场景随信息揭示而改变。情节沿原文推进，不编造分支结局。

完整原文始终可切换，返回互动阅读后保留操作状态。生日概率、Redis、HNSW、摄影、中子星、火星通信、买房账本、食物组成、天气操作和十年桌子，则展示不同内容如何选择各自适合的交互形式。

## 创作者如何使用

创作者通过知乎账号登录，导入正文并填写表达想法，再生成和预览交互作品。个人作品默认私有，可保存版本；个人草稿与公共精选分开，旧副本不会覆盖首页。当前已实证一个真实账号完成知乎授权、一次个人生成和后台保存。

默认十七篇由当前 Codex 会话逐篇创作与修订，保存真实会话来源；用户在线生成采用 DeepSeek。两者的创作来源分别记录，不把人工修订的精选伪装成 API 自动生成结果。

生成服务按「整篇设计约定 → 分块代码 → 装配检查 → 局部修复」运行，每任务最多两次修复。前端显示任务进度，并在生成期间每约五秒查询服务端任务状态，避免流式连接缓冲时一直停留在“正在连接”。失败明确返回原因，保留已有作品。

## 与知乎社区的结合

专业回答可以变成可验证的推导，经验回答可以变成条件比较，故事可以变成视角探索。交互帮助读者理解和回看作者的表达，也为创作者提供文字之外的表达工具。

网站已接入知乎 OAuth 基础身份识别。讨论发现入口读取官方讨论、摘要及来源；采集侧接入具备权限的本人全文与活动知识、故事详情。摘要和全文严格区分：普通回答摘要不被包装成完整回答，登录也不意味着可以读取任意知友全文。

作者、来源链接、获取范围和补充假设保留在内容中。导入素材清洗时保留快照和差异记录，重复界面文字可以清理，论证、引用和原图不会机械删除。

## 技术方案

前端使用 Svelte，服务端使用 Hono，部署于 Sites 的 Worker 环境。D1 保存用户、作品版本、任务和额度，R2 保存媒体与产物。登录凭证和模型密钥仅存服务端；会话使用 HttpOnly Cookie，工作区按服务端用户身份读写，并校验保存版本。

模型生成 HTML、CSS 和 JavaScript，由隔离 iframe 执行。Runtime 负责按可见区域加载、注入已校验的原图和处理失败回退；生成代码不自行联网，也不能访问宿主页面。宿主只排列和运行作品，不按文章题材分配固定模板。

线上默认额度为每人每日 10 次、全站用户生成每日 100 次，重试属于同一任务。素材、备注、清洗记录与历史版本保留，当前公开版本可回退。
