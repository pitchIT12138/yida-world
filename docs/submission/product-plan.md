# 一答一世界

让文字没有说完的，变成一次亲手探索。

## 为什么做这个产品

知乎有大量值得反复阅读的回答。有些难点不在文字写得不清楚，而在读者需要亲自改变一个条件，才能理解作者的推导：生日概率中的“两两比较”、现金流随时间折现、人口结构与供养比的不同口径。故事也有类似空间：人物所见与读者已知的差异，可以通过叙事视角的切换变得可感。

一答一世界把程序作为回答的另一种表达语言。原文保留在阅读的中心，交互分散在相关句段旁。读者可以做一次比较、推演一个情景、揭开一条线索，再带着观察回到作者的论点。

## 为谁解决什么问题

对读者，它提供从“看过”走向“理解”的入口；对创作者，它让已有文章可以生长出图示、实验和叙事体验，而不必先学习编程。评审和首次访问的读者无需登录即可体验精选；创作和个人作品保存使用知乎账号登录。

作品保留作者、来源和原文范围。原创演示与真实知乎内容分别标明，真实回答优先展示。模型补充的计算和情景假设清晰可辨，读者可随时切回原文。

## 主要体验

- 原文阅读：保留段落、公式、引用、表格和原图，交互失败时仍能阅读。
- 交互解读：模型按文章自行选择直接操作、机制模拟、图示比较或叙事场景，各篇不套用统一题材模板。
- 设计讲解：说明为什么在这里安排操作，以及操作结果如何帮助理解。
- 个人创作：登录后导入正文、填写想法、生成和保存自己的版本，作品默认私有。
- 讨论发现：展示官方接口提供的热点与摘要，保留原文入口。
- 交互新作：取得正文后进入生成和验收流程，通过检查的版本再上架。

## 知乎能力的结合方式

使用知乎 OAuth 完成登录和基础身份识别；使用热榜发现讨论；使用活动知识、故事接口及具备权限的本人全文接口取得正文。摘要和全文严格区分：普通问题回答接口的摘要不会被包装成完整回答，本人全文能力也不被描述成可读取任意知友全文。

这个设计适配知乎社区对专业论证、经验分享和长篇叙事的需要。它不替作者改写结论，而是帮助读者观察条件与结论的关系，也让创作者能解释自己的表达选择。

## 技术实现

前端采用 Svelte，接口采用 Hono；网站部署在 Sites 的 Worker 环境，D1 保存账号、版本、任务与额度，R2 保存媒体和产物。DeepSeek 读取原文后输出 HTML、CSS、JavaScript；统一 Runtime 在隔离的 iframe 中执行，生成代码无法联网或读取宿主页面。

线上创作与后台生产共用生成和校验服务，记录实际模型、原文指纹、用量和修复次数。后台使用独立私有仓库的 GitHub Actions，串联采集、生成、内容检查、桌面与手机实际操作及上架。首发由管理员手动触发，定时更新默认关闭。

每个任务最多两次修复；失败保留候选和证据，已有合格版本继续展示。素材清洗、作者备注和历史版本均保留，版本冲突不会静默覆盖。

## 2026-09-15 发布前体验更新

首页固定为 DLSS、老龄化、DCF、租售比、国考、近视故事、小胜与闭合回路，再接10篇原创演示。五篇真实回答有紧凑导航；首屏直接显示已核对的一组 DLSS 原图和可拖动分隔线。

每篇指定一个核心交互，前置运行一次；其他操作沿原文分散展示，不再随补充正文折叠。公共精选与个人旧副本分开读取。DLSS支持联动放大平移，DCF支持单年覆盖与方案比较，人口、房屋租赁、食物组成和月度账本可以自由输入，故事通过空间与信息视角展开。

本次公开交付以完整阅读演示为准。正确 OAuth 配置保留，但真实授权、个人生成保存及双账号隔离尚未完成最终验收；GitHub 内容生产保持暂停。上述后续能力不作为已验证的参赛演示功能。
