# 生成连接与任务状态

生成期间，SSE 每 5 秒回报当前阶段及经过时间。模型返回 HTTP 响应后才显示“模型已响应”；等待时不把宿主心跳宣称为模型健康检查。

页面同时每 5 秒读取 `/api/generation/:id`，使用当前登录身份核对任务归属。读取不触发模型、不占生成次数。每次生成提交带独立请求标识；同一标识重复提交拒绝，不能重复消耗额度。修复继续沿用原任务及两次修复限制，用新的请求标识区分旧结果。

进度与完整结果保存在私有 R2 路径，写入按顺序执行，避免早期进度覆盖最终结果。返回结果前完成保存。状态查询只能由原用户或对应管理员任务身份访问。

首次确认最多等待 20 秒；收到进度后超过 30 秒没有新状态则报告连接中断。总等待受服务端配置上限约束。端点可访问但任务状态陈旧时，不算任务仍在运行。取消和结束时清除查询与计时器，保留原文及上一版。

该机制用于正在生成的任务，不是定时重新生成，也不是空闲时不断调用收费模型。页面刷新后不会自动重发模型请求。旧版生成未保存最终结果的任务不能靠此机制追溯恢复。

回归：`tests/generation-connection.test.ts` 覆盖进度缓冲、结果查询恢复、失联、取消、过期状态、服务错误和账号隔离。`tests/generation-production.integration.ts` 使用真实线上模型和管理员额度验证进度、最终结果、未登录拒绝及重复提交；候选不公开上架。
