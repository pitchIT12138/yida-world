# 持续打磨工作区

本地开发服务使用 SQLite 保存回答，文件为 `web/.data/workspace.sqlite`。打开页面时先读取后台，再迁移当前浏览器以前保存的回答。相同后台的空白浏览器可以恢复这些记录；生成想法也会随回答保存。

## 页面操作

- 每篇回答下方的“编辑原文”可以修改标题、作者和正文段落。“保存修改”更新原回答，不再复制成另一篇。
- “加工回答 / 还想怎么改”中的想法与段落选区自动保存，输入停止约 400ms 后提交后台。页面显示保存状态。
- 修改原文保留旧版本。若原文改变，旧产物移为历史参考，下次生成同时携带新原文及旧原文、代码、设计说明。
- 导入、修改原文、生成成功、生成失败和恢复版本会追加历史记录；连续输入只更新当前草稿，避免每个按键形成一个历史版本。
- “版本历史”可以查看当时的想法与产物说明，选择“使用这一版继续打磨”。恢复本身也会追加记录，后面的版本不会被删除。
- 模型未接入时仍可编辑与保存想法，生成按钮明确显示未配置。当前运行中的生成请求不会在刷新后自动续跑；已保存的想法、原文和完整结果保留。

正文编辑器在点“保存修改”后才提交；未保存的正文输入不等同于已保存版本。想法输入具有自动保存。

## 存储与备份

后台是当前本地服务的持久存储；IndexedDB 保留浏览器备份和未提交的修改。网络失败时显示“后台未保存”，不会把失败当成保存成功。重新打开页面会恢复浏览器待保存草稿；后台版本没有变化时继续提交，有变化时提示核对后台版本。乐观版本号阻止旧窗口静默覆盖新窗口。

SQLite 中的 `answers` 保存当前状态，`versions` 保存完整历史，`assets` 按 SHA-256 去重保存媒体数据。同一次版本更新使用事务。回答和图片未发送到第三方存储；调用模型时发送的上下文遵循生成接口。

完整备份：先停止本地开发服务，再复制整个 `.data` 目录。运行中的 SQLite 可能有 `-wal` 与 `-shm` 文件，不应只复制主文件。浏览器里的“备份当前预览”导出当前回答快照，不含后台所有历史版本。

`.data` 已加入 Git 忽略。这个适配器仅用于本地 Node 服务；静态预览和当前 Worker 发布包不包含 SQLite。未来云端需要接入 `WorkspaceStore` 的持久数据库适配器及用户隔离，当前没有部署云端工作区。

## 模型插槽

经济档使用 `BALANCED_*`，之后可以选择 DeepSeek 或 Qwen3 的服务；高能力档使用 `FRONTIER_*`，预留 Astral 中转站。当前按用户要求留空真实地址、精确模型 ID 和密钥。每档可独立配置，兼容 OpenAI Chat Completions 或 Anthropic Messages 协议。

将实际服务提供的 API base、model 和 key 填入被忽略的 `.dev.vars`；模型名不从展示名称猜测。`*_PROVIDER` 填 `openai-compatible` 或 `anthropic`。服务端分别追加 `/chat/completions` 或 `/messages`。密钥只在服务端使用，页面仅收到可用档位。

点击“刷新模型配置”重新读取配置完整性；这不执行模型调用，也不证明上游鉴权成功。填写凭证后，在回答上真实生成一次，才能完成网络、鉴权与输出质量验收。暂不自动调用供应商做付费测试。

## 验证

`npm test` 包含真实 SQLite 的事务、重启恢复、历史保留与过期写入拒绝测试。

`npm run test:workspace-ui` 使用隔离数据库和空白浏览器执行真实界面流程：导入、编辑、保存想法、关闭重开数据库、换空白浏览器恢复、生成两版、编辑后传递旧代码、恢复历史。只有生成上游明确使用测试夹具，不代表真实供应商质量。需要先运行本地开发服务。
