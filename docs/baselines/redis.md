# 请求没有变少，为什么一批发送会更快？

基线版本：session-repair-2026-09-14

## 整篇表达

让每一段网络等待占据时间轴，改变批次后只压缩等待；存在前后依赖时禁止提前合批。

公式处跑两条队列 → 末段改变依赖和批次，检验加速条件。

## 片段分工

### 命令还在，消失的是空等

- 稳定 ID：network-tracks
- 位置：redis-p1
- 形式：experience

表达任务：批处理改变等待段数量，不改变处理总量；时间游标对应已完成命令数量。

放在这里的理由：紧接对应原文：Pipeline 的核心不是让命令凭空消失，而是把多条命令先发出去，再读取响应。简化示意下，逐条等待约花 6×(80+2) 毫秒，一批发送约花 80+6×2 毫秒。

操作与反馈：改批次大小并推进一批；再开启依赖，观察队列退回逐条等待。

实现约定：独立沙箱内 HTML、CSS 与 SVG；共享状态只经 world 协议。
