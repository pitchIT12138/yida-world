# 文章表达基线

这里保存当前 Codex 作为内容生成 Agent 的可复用设计记录。记录面向作者与后续模型，说明设计目标、理由和取舍，不声称还原模型内部推理。

每篇从完整原文出发，先设计阅读路线，再决定哪些位置值得增强。短选择、句旁注释、图示、物件操作与正文反馈可以共同出现；数量和形式由内容决定，不要求每篇有相同组件数。所有视觉仅由代码产生。

## 三层记录

1. `src/lib/design-policy.ts`：跨文章原则与产物要求，每次模型调用都读取。
2. 本目录每篇 Markdown 与 `src/data/baselines/catalog.json`：整篇风格、每个片段的任务、位置理由、反馈、实现方式和验收要求。API 优先延续当前产物中的基线；原文指纹相符时才使用精选基线。
3. `artifacts/baseline-history`：按内容指纹追加的历史快照，包含对应代码指纹与真实生成记录，已有快照不覆盖。

## 每次迭代

- 先读原文、当前产物和对应基线。用户的新要求优先。
- 明确此次改动涉及哪些段落和片段，保留其他内容及其设计记录。
- 若改变风格、操作或分工，同步更新设计说明与版本，说明新的取舍。
- 实际操作控件、检查正文与片段联动，再记录验收结果并提升为精选。
- 运行 `npm run baselines`，同步当前目录、模型目录和历史快照。

接口记录本次采用的 baselineVersion 与 baselineHash，便于跨模型比较。传递同一约定可以约束输出，但不能代替真实模型的质量评测。

## 设计讲解

默认手动翻步，可以回看；自动模式每步至少 8 秒，长说明停留更久。步骤解释整篇阅读路线、片段位置和交互理由，演示指令在当前 iframe 中点击或输入，并等待运行回执。失败会显示失败状态，不伪装执行成功。这是此前设计的可重复讲解，不是实时 Agent 工具日志。

## 跨文章复用

内部工作台及 `library/interactions` 将经验与可改编代码共同保存，详见 [工作台流程](../studio.md)。文章基线记录该篇设计；交互库记录跨文章适用条件与实现版本。产物的 libraryReferences 记录复用/改编关系；当前作者备注和当前文章事实优先。库资产通过实际操作验收后入库，不由宿主按题材套用。
